# NASitron

A self-hosted OpenZFS monitoring dashboard and storage workspace for Ubuntu NAS hosts. Monitor pool health, drives, historical I/O and alerts; manage snapshots, replication and reviewed storage operations over SSH.

[Website & guides](https://nasitron.bobcronin.com) · [Report an issue](https://github.com/StealthCat/NASitron/issues)

## Requirements

**Dashboard host:** Docker Engine with the Docker Compose plugin, Git and OpenSSL. The supplied stack includes NASitron and Caddy for HTTPS.

**NAS hosts:** Ubuntu with OpenZFS, SSH access and an administrator account with sudo for enrollment. The installer prepares the dedicated monitoring account and required tools.

The dashboard must reach each NAS over SSH. Each NAS must reach the dashboard over HTTPS during enrollment. Allow inbound dashboard ports 80 and 443, or choose alternate host ports in `.env`.

## Quick start

### 1. Download and configure

```bash
git clone https://github.com/StealthCat/NASitron.git
cd NASitron
cp .env.example .env
chmod 600 .env
openssl rand -hex 32
```

Edit `.env` and set:

| Setting | Value |
| --- | --- |
| `NASITRON_SECRET_KEY` | The value generated by OpenSSL above |
| `NASITRON_WEB_USERNAME` | Your initial administrator username |
| `NASITRON_WEB_PASSWORD` | A unique password of at least 12 characters |
| `NASITRON_TLS_HOST` | Your dashboard hostname or IP, without `https://` |
| `NASITRON_TIMEZONE` | Your IANA timezone, such as `America/New_York` |

**Keep the secret key stable and back it up.** It encrypts stored SSH and email credentials; changing it makes those existing secrets unreadable. Keep `.env` out of source control.

The administrator credentials seed the first account. After that, manage users and passwords through **Users** in the dashboard.

### 2. Start the dashboard

```bash
docker compose up -d --build
docker compose ps
```

Open `https://YOUR-DASHBOARD-HOST` and sign in with your administrator credentials. If you changed the HTTPS port, include it in the URL.

Caddy initially uses its internal certificate authority. Trust that CA on your clients, or configure an uploaded certificate or ACME in **Settings → HTTPS**. Public ACME validation requires the configured hostname to resolve to your server and the validation ports to be reachable.

If ports 80 or 443 are already in use, change `NASITRON_HTTP_PORT` and `NASITRON_HTTPS_PORT` before starting. `NASITRON_LISTEN_IP` controls the host address Caddy binds to. The application’s port 8080 stays private inside the Compose network.

### 3. Add a NAS

1. Open **Add Server** in the dashboard.
2. Copy the generated one-time enrollment command.
3. Run it on the NAS using an account with sudo.
4. Wait for the registration-complete message, then confirm the server appears and collects telemetry.

Use the exact command shown by your dashboard. Internal-CA deployments provide a checksum-verified enrollment command. The SSH private key stays encrypted inside NASitron; the one-time enrollment expires after 30 minutes.

Verify the NAS SSH host-key fingerprint through a trusted channel and enable strict host-key checking. After enrollment, check collection freshness, pool identities and drive inventory.

### Privileged remote helper

Enrollment installs a dedicated account, SSH configuration and a root-owned helper with a narrowly scoped sudo rule. Keep those permissions restricted to the helper; do not grant unrestricted sudo or direct wildcard access to ZFS commands.

For manual setup from a NASitron checkout on the NAS, supply your dedicated SSH public key:

```bash
sudo bash scripts/install-remote.sh --public-key-file /path/to/nasitron-monitoring.pub
```

Then enter the connection details and matching private key in Add Server. Use `bash scripts/install-remote.sh --help` for installer options. Prefer the dashboard’s enrollment command for automatic registration.

## After setup

- Configure **Settings → Email** for SMTP or a Mailjet-compatible API and send a test message.
- Review **Health** thresholds and **History** retention in Settings.
- Map enclosures and drive bays to physical hardware.
- Open a server’s **Storage workspace** for snapshots, replication, expansion planning and administration. Create schedules explicitly; setup does not enable recurring storage changes.

Administrative changes require appropriate permissions, HTTPS and confirmation. An **Accepted** result means a command was submitted successfully; follow Operations to verify background work has finished.

## Everyday commands

Run these from your NASitron checkout:

```bash
# View recent logs
docker compose logs --tail=100 nasitron caddy

# Restart services
docker compose restart

# Stop services while preserving their data volumes
docker compose down
```

NASitron stores its database, credentials, host keys, settings and history in `nasitron_data`. Caddy uses `caddy_data` and `caddy_config`. Keep the same checkout/project name when restarting so Compose continues using the same volumes. Do not use `docker compose down -v` unless you intend to delete the deployment’s data.

## Back up and update

Back up `.env`, deployment configuration, NASitron’s data and Caddy’s certificate/CA state before updating. The application includes an offline encrypted backup utility; follow the [backup and restore instructions](docs/PREVIEW.md#encrypted-backup-and-restore).

To update this source-built Compose deployment:

```bash
git pull --ff-only
docker compose up -d --build
docker compose ps
```

Then open **Servers → Upgrade Server** for each existing NAS and run its generated command on that host. This updates the helper while preserving enrollment, credentials, labels and history. Poll the server and refresh storage inventory afterward.

Keep NASitron at one application worker/replica per data directory; the supplied stack sets `WEB_CONCURRENCY=1`.

## Troubleshooting

| Problem | Check |
| --- | --- |
| Dashboard does not start | Check Compose logs, required `.env` values and port conflicts. |
| Browser does not trust HTTPS | Trust Caddy’s internal CA or configure a trusted certificate in Settings → HTTPS. |
| Enrollment does not finish | Check the installer output, NAS-to-dashboard HTTPS access and whether the one-time command has expired. |
| Server has no fresh telemetry | Check dashboard-to-NAS SSH access, credentials, host-key verification and the reported collection error. |
| Storage actions need a newer helper | Use Servers → Upgrade Server, then poll and refresh inventory. |
